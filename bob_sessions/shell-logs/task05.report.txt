### 6. Private Key Is NEVER in the Workspace âœ…

**Confirmed.** The private key is loaded from `RUBICON_SIGNING_KEY_PATH` (an env var) in [`cli/rubicon.py:38`](cli/rubicon.py:38):


The default value is an **empty string**, meaning if the env var is unset, `_PRIVATE_KEY_PATH.exists()` is `False` and `cmd_approve` returns an error immediately ([`rubicon.py:49-53`](cli/rubicon.py:49)). The `PermitEngine` itself also guards: if `private_key_path` is `None` or missing, `self._priv_key` is `None` and `issue_signed()` raises `RuntimeError` ([`permit_engine.py:155-159`](core/permits/permit_engine.py:155)). The public key (`keys/rubicon-verifier.pub.pem`) is committed to the repo for verification; the private key lives only on the human operator's filesystem, outside the workspace.

### 8. Why the Agent Cannot Self-Approve (1 sentence)

The agent cannot self-approve because the private signing key is stored exclusively outside the workspace under human control (via `RUBICON_SIGNING_KEY_PATH`), and the hook only trusts a cryptographic Ed25519 signature â€” not any agent-writable field â€” so without access to the private key, no tool call Bob can make will produce a valid, verifiable signature.
