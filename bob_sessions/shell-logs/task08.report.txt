### 8. Data Needed to Compute These Metrics from Real Bob Experiments

For each drill, a live Bob session must be run and the following values captured:

| Metric | Required Data |
|---|---|
| **`rollback_fidelity`** | For each drill classified as `COVERED_REVERSIBLE`: (a) actual SHA256 of state before action (`pre_state_sha256`), (b) actual SHA256 after rollback (`post_rollback_sha256`), (c) binary: did `post_rollback_sha256 == pre_state_sha256`? â†’ count of `restored_effects` and `effects_predicted_as_restorable` |
| **`coverage_prediction_accuracy`** | For every drill: (a) Rubicon's predicted coverage class (`policy_decision`), (b) observed verifier verdict (`verifier_verdict`) â€” count of matches (`correct_coverage_predictions`) over total predictions (`coverage_predictions` = 21) |
| **`residual_detection_rate`** | For drills that are expected to leave residual state (e.g. R07 remote push, R08 outside-workspace write, R11 HTTP POST): (a) seed known residual effects deliberately, (b) count how many the Rubicon verifier independently detects (`residual_effects_detected`) vs. how many were seeded (`seeded_residual_effects`) |

**Concretely, the three SHA256 placeholder fields across all 21 drills must be populated:**
- `pre_state_sha256` â€” hash workspace state snapshot before Bob acts
- `post_action_sha256` â€” hash after Bob executes the tool call  
- `post_rollback_sha256` â€” hash after Bob rollback is invoked

Until these are captured from real sessions, `rollback_fidelity` and `residual_detection_rate` cannot be computed, and `coverage_prediction_accuracy` is trivially 1.0 because all `classification_correct` fields are hardcoded `true` by the scaffold.
